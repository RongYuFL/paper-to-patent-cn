# 附图与文件交付要求

当任务包含附图或Word文档时使用本参考，不据此扩展纯文字或局部修改任务。本模块按主文件确定的申请类别和交付范围安排附图，不扩大任务。

## 附图组成与顺序

完整文档以图1“方法流程示意图”和图2“系统结构示意图”为两张基础图，分别表示步骤关系与模型或功能模块的逻辑结构。用户限定仅写方法时，图2仍可用作方法架构说明。

两张基础图之后，可按方案需要或用户要求增加模型细节图、训练流程图、关键模块图、局部处理图及应用图。只画能解释技术关系的图，不为凑图数制造重复内容。

申请范围包含系统、设备或存储介质时，在全部基础图和技术细节图之后设置实现结构图，作为最后一张。多个类别可用一张综合图说明；图号按实际数量连续编排，不写死最后图号。用户指定部分范围时，调整最后一张图的内容；明确仅写方法时，以所需技术图结束，不默认补画通用计算机或载体图。

## 参考文件的使用

先查看最新指定参考专利的实际页面，尤其是与当前方案对应的方法图、模型结构图、系统图或设备图；不能仅凭提取文字或通用流程图习惯重建其版式。若用户指定第二份或新模板，应以该文件为准，不退回早期参考。缺少参考时先利用已有明确要求完成可做部分，涉及无法确定的关键图式再询问。

参考页面只用于当前图形与排布；不移植无关技术内容、模块名称或编号。

## 摘要附图

有说明书附图时，从中选择最能体现核心技术特征的一幅，默认仅以文字指定“摘要附图：图X”。图1方法流程图、图2系统结构图或其他图均可作为候选，不固定选择图1。所指定图号必须与说明书附图一致，不另画新图、不新增说明书图号。

撰写稿不为摘要重复插入所选图片，也不单设摘要附图页。用户明确要求提供图片副本、独立文件，或其指定的正式提交模板另有排布要求时，再按该要求处理。正式申请时，在请求书中指定所选图号。[国家知识产权局关于摘要附图的说明](https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?sysid=6&transactId=497734)

## 图1 方法流程示意图

图1称为“方法流程示意图”。展示与公共方法步骤对应的处理过程，并使用具体实施方式已经定义的Sxxx编号。

默认采用以下标注形式；用户指定其他形式时按其要求调整：步骤编号放在步骤框旁，通过曲线或弯曲引出标注与对应框建立关系。查看参考确认曲线的走向和定位方式；不要仅将“S110”直接塞进框内标题，也不要用流程箭头替代编号标注曲线。

流程连接与步骤标注应容易区分。按实际依赖关系画出顺序、并行、迭代或反馈过程，只有实际存在多分支时才设置并行路径。模型运算、数据、监督信号或控制状态的必要辅助连接应画出，不因主流程简化而消失。

## 图2 系统结构示意图

图2作为基础图展示模型或功能模块的逻辑结构，默认完整稿与系统方案说明对应；用户限定仅写方法时，仍可用该图说明方法的处理架构，不据此增加申请类别。保留已认可的流程层次和主要处理框，用虚线外框将属于同一模块的若干步骤或子处理归组，并标出模块名称及模块编号。不要为了强调模块而将原图强行压缩成每个模块仅剩一个方框的简略串行图。

分组应与具体实施方式中对模块及其处理的描述一致；申请范围包含系统时，同时与系统方案正文一致。明确模块之间的主数据路径、并行关系及汇合关系；编码、预测、优化、交互或输出模块之间的连接应符合真实输入输出；训练图中的监督与参数更新连接不能误画成推理必需输入。

修订现有图时优先保留用户已认可的框、连接及布局，再调整分组边界；不要重新发明一套图形结构而丢失原图内容。

## 技术层次与图中命名

基本方法图、系统图及公共步骤使用与基本技术方案同层级的名称，不将某个可选算子、网络实例或训练策略提升为所有方案的固定标签。具体结构、算子和实现细节在相应改进实施例或细节图中展开，同时保留足以区分核心发明点的信息，不能将所有节点泛化为没有技术含义的“模型处理”。

算法名、网络型号、固定时间长度、帧数、特征维度、训练轮数及具体数据比例，不默认写入通用图中。除非构成必要技术特征，图中呈现处理关系而不是某次实验配置。

基本结构和改进结构需要不同图时分别说明，不把可选模块、辅助路径或训练策略画成所有配置都必须具备的环节。训练过程与推理过程需要分别解释时，分别作图，不预设固定的预训练、独立训练和融合训练三阶段。

## 最后一张 实现结构图

默认完整稿提供该图，并与系统、设备及存储介质的正文和权利要求对应。用户指定部分范围时，按所保留的类别调整；明确仅写方法时不默认提供通用设备实现图。图题和内容依据实际范围确定，不能只画图而缺少正文解释。

涉及设备时，可采用电子设备结构示意图，画出处理器、存储器及二者连接，并说明存储的程序如何被处理器执行以实现方法。总线、通信装置或其他接口按实际需要设置，避免将可选网络连接写成执行方法的必要条件。

涉及存储介质时，在最后一张图中说明程序或指令的存储载体及其与执行过程的关系。与设备范围同时要求时，可结合处理器、存储器和所存程序用同一张图说明；无需仅为介质另添一张同义图，用户限定仅有介质范围时，不因图示执行关系额外增加设备权利要求。

仅要求系统范围时，最后一张图可展示系统的实现或部署结构，说明与图2功能逻辑结构不同的实现层次；不为满足图数默认添加设备或介质类别。所有部件编号和数据连接均应在对应正文中解释。

## 可编辑性与视觉核对

专利流程图优先采用可编辑的矢量或代码绘图工具实现，保持黑白可辨、线型清晰、中文字体一致。无需用生成式位图工具制作需要精确编号和连接的工程图。

核对步骤曲线与流程箭头是否可区分，虚线框是否正确归组，是否有文字或连接线重叠，线条是否穿过文字，以及插入Word后字号和线宽是否仍可读。附图说明、图号、步骤号、模块号与正文逐项一致。

## Word排版与文件生成

### 格式依据与默认样式

先沿用用户指定的Word模板或现稿样式，其次参考用户指定专利的实际页面；不要只提取文字而忽略格式。只有缺少明确样式时，才使用下表的可编辑审阅稿默认值。该表是排版起点，不是对所有正式申请的强制规定；正式提交时依适用的官方模板及提交要求调整。[国家知识产权局关于说明书字体设置的答复](https://www.cnipa.gov.cn/jact/front/mailpubdetail.do?sysid=6&transactId=459720)

| 项目 | 无指定模板时的审阅稿默认值 |
| --- | --- |
| 页面 | A4、纵向、单栏；上和左页边距25毫米，右和下15毫米 |
| 正文字体 | 中文宋体小四（12磅），英文和数字Times New Roman 12磅，黑色 |
| 标题 | 各部分总标题及发明名称居中；章节标题、实施例标题独立成段并左对齐；总标题可用14磅，其余12磅，适度加粗区分层级 |
| 正文段落 | 两端对齐、首行缩进2字符、段前段后0磅、1.5倍行距 |
| 特殊段落 | 标题、公式、图号等使用独立样式，不继承正文首行缩进；权利要求保留项号和步骤分段 |
| 页眉页脚 | 不增设装饰性页眉；审阅稿可在页脚居中使用自动连续页码，模板另有要求时依模板 |

用Word样式管理正文、标题、实施例标题、公式及图号，不用连续空格模拟对齐，也不用大量空段落制造分页。不要将审阅稿字号或倍数行距直接等同于正式提交要求中的实际字高、字间空白或行间距；需要提交时按对应模板及实际渲染结果核对。

### 分页与页码

摘要、权利要求书、说明书及说明书附图分别起新页，用分页符或必要的分节符控制。标题与其后内容保持同页，避免章节或实施例标题孤立在页末；图号与对应图片保持同页。摘要附图沿用本文件的文字指定规则，不因分节另增摘要附图页。

正式申请各组成文件的页码按适用提交模板分别设置；合并审阅稿的连续页码不应被误用为正式提交规则。使用自动页码字段，不手工逐页输入页码。用户要求独立文件时，按所需文件分别组织，不为方便排版改变正文内容。

### 公式与图片

新增公式采用可编辑的原生数学结构或等效编辑能力，默认数学字体可用Cambria Math；不将公式默认做成图片。显示公式居中，编号靠右，使用制表位或稳定的对齐结构；不能靠堆叠空格对齐。优先采用不会裁切上下标、分式和矩阵的行距设置，必要时仅调整公式段，不强行压缩公式适配固定行高。公式编号和交叉引用与原稿衔接，修改项数或结构后复核引用。

附图集中置于说明书附图部分，说明书文字中引用对应图号；图片按比例缩放，宽度不超出版心，避免拉伸、裁切或缩小至文字不可读。图号置于图下方居中，其他图题排布依模板；多图排页应保持清晰间距和完整连接线。图形技术规范按本文件对应章节执行，不在Word生成时另造不同样式。

### 文件操作与验证

创建或修改DOCX时，使用当前环境可用的documents技能完成文件操作及渲染检查。原稿存在原生公式、字段、图形或段落样式时，尽量定点修改，不用普通文本重建而丢失结构。不套入演示文稿或宣传册的装饰设计，不把模板注意事项、样例提示或内部检查记录保留在最终正文中。

完成实际文件修改后渲染并检查最终页面，核对页面尺寸与页边距、字体及行距、权利要求分段、标题分页、页码、公式上下标和图中文字。确认没有裁切、重叠、空白异常或字体替换。排版核对不能用纯文本提取代替，只交付经过检查的最终文件。

## 附图交付前核对

按本次实际交付核对基础图、最后一张实现结构图及摘要附图的对应关系；图1的框旁曲线标注与流程箭头应可区分，图2的虚线归组应保留内部处理与连接。修改或插入图片后，同时核对正文图号、图题、步骤号、模块号及摘要附图指定，不能仅检查图文件本身。
